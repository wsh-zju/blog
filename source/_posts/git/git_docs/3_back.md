## 查看仓库状态

1. **修改 txt 文件内容如下**

   ```txt
   Git is a distributed version control system.
   ```

2. **查看仓库当前状态**

   ```bash
   git status
   ```

   终端会显示 readme.txt 文件被修改了

3. **查看具体的修改内容**

   ```bash
   git diff
   ```

## 版本回退

通过之前的练习，你已经学会了修改文件，然后把修改提交到 Git 版本库。每当你觉得文件修改到一定程度的时候，就可以“保存一个快照”，这个快照也就是 commit。

一旦你把文件改乱了，或者误删了文件，还可以从最近的一个 commit 恢复，然后继续工作，而不是把几个月的工作成果全部丢失。

1. **查看历史提交记录**：

   - 版本控制系统可以帮助我们记录每次修改的内容，输入

     ```bash
     git log
     ```

     可以在终端看到**从最近到最远的提交日志**，包含版本号、作者、时间以及提交说明

   - 当然，如果觉得输出信息太多，我们也有**更简洁**的查看方式

     ```bash
     git log --pretty=oneline 
     ```

     这样就会只显示版本号和提交说明

2. **版本回退**：如果我们想要回退到上一个版本，输入

   ```bash
   git reset --hard HEAD^
   ```

   就可以回退到上一个已提交版本

   - 当然，这个命令使用**不同参数**也会产生不一样的效果
     - `--hard`：回退到上个版本的**已提交**状态
     - `--soft`：回退到上个版本的**未提交**状态
     - `--mixed`：回退到上个版本**已添加但未提交**的状态
   - 这里的 `HEAD` 表示当前版本
     - `HEAD^` 表示上一个版本，`HEAD^^` 表示上上个版本
     - 当然，往上 100 个版本不太可能写100 个`^`来表示，可以使用 `HEAD~100`

## **重返未来**

回退版本我们学会了，但是假如我们后悔回退版本了，应该怎么返回之前的新版本呢？

1. 想要回到某个新的版本，**最重要的是**找到那次 commit 对应的版本号

2. 但是这时候如果我们使用

   ```bash
   git log
   ```

   发现回退版本之后，之前最新的提交记录已经被抹去了

3. 但是不要慌，Git 还提供了一个用来**记录你每一次操作**的命令

   ```bash
   git reflog
   ```

   这样我们就可以看到之前 `reset` 的操作，以及每一次操作的版本

4. 记录下来需要的版本号，利用命令

   ```bash
   git reset --hard 72ba9fe  # 版本号
   ```

   就可以回到指定的那个版本啦

## 撤销修改

如果我们在工作区对 `readme.txt` 文件做了很多修改，但是发现很多都是错误的或者无意义的，想要撤销在工作区的所有修改，我们该怎么办？

此时，存在两种不同的情况：

1. **`readme.txt` 文件修改后还没有被放到暂存区**：执行

   ```bash
   git checkout -- readme.txt    # s用版本库里的版本替换工作区的版本
   ```

   我们就可以回到上次 `commit` 之后的状态

2. **`readme.txt` 文件修改后已经被放到暂存区**（但是还没有 `commit`）：执行

   ```bash
   git reset HEAD readme.txt		# git reset HEAD <file>
   ```

   可以**取消暂存的修改**，这时候再执行

   ```bash
   git checkout -- readme.txt
   ```

   就可以丢弃上次 `commit` 之后工作区的修改

假设很不幸的是，`readme.txt` 文件修改后已经被**从暂存区提交到了版本库**，想要撤销提交，那就要使用之前学习的 [版本回退](#2-版本回退) 的知识了。

## 文件删除

1. **新建文件** `test.txt`，并提交到版本库

2. 如果想要从版本库中删除该文件，则执行

   ```bash
   git rm test.txt
   git commit -m "提交说明"
   ```
